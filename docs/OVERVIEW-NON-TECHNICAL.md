## 0. 一句话讲清

> **YKT AI SaaS 平台是 ykt 工作区的"AI 中枢"**：第一服务对象是**自家的小智 AI 设备**（MVP 即接入），同时对外开放多租户。你不用自己建模型、不用自己买显卡、不用自己写语音识别。注册一个账号、领一把"钥匙"（API Key），就能在你的产品里调用 ChatGPT 同款的大模型、合成真人般的语音、识别客户说话、定制自己的 AI 助手。

**平台的双重身份**：
- **对内**：小智 AI 设备的"AI 大脑"（xiaozhi-server 改造后只管设备协议，AI 调用全部走平台）
- **对外**：面向第三方企业/开发者的 AI 能力 SaaS

按月付费，按量计费，多家企业共用一套平台但**数据完全隔离**，互不窥视。

## 1. 平台能做什么（场景化）

### 1.1 十大能力 → 业务场景

| 能力 | 业务场景举例 |
|---|---|
| **大模型对话（LLM）** | 客服机器人自动回消息、AI 写公文、代码助手、营销文案生成 |
| **语音合成（TTS）** | 把新闻播报出来、把儿童绘本读给孩子听、有声书生成 |
| **语音识别（ASR）** | 会议录音转文字、客服电话质检、语音搜索 |
| **情绪识别** | 客户来电情绪检测、AI 客服按情绪调整语气 |
| **声音克隆** | 复刻 CEO 的声音做公司宣传片、给盲人复刻亲人声音 |
| **性格人设（Persona）** | 让 AI 用"东北大爷"语气聊天、用"温柔姐姐"做儿童陪伴 |
| **知识库（RAG）** | 上传公司产品手册，AI 只回答手册内容（不胡说） |
| **工具调用（MCP）** | 让 AI 查实时天气、查物流、查日历、控制 IoT 设备 |
| **流式响应** | 一边生成一边显示（打字机效果），不用等几秒钟 |
| **模型微调** | 用公司积累的客服对话训练专属模型，回答更专业 |

### 1.2 一个真实业务串联

**场景：智能教育 App 接入**

```
学生打开 App："帮我讲讲勾股定理"
   │
   ▼ ① 调用 LLM（大模型对话）
平台收到 → 检查是"学而思"租户 → 检查套餐还有额度
       → 用 Persona"温柔老师"的语气 → 检索"初中数学"知识库
       → 流式返回："勾股定理说的是……"

   │ ② 学生说"我没太懂"
   ▼ 调用 ASR（语音识别）
平台把语音转文字 → 加上识别到的"困惑"情绪

   │ ③ 重新生成回答 + TTS（合成老师声音）
平台用"温柔老师"的克隆声音把答案说出来
       → 自动放慢语速 0.9 倍（情绪影响）

   │ ④ 全程自动计量计费
平台记录：本次用了 LLM 350 token、ASR 8 秒、TTS 12 秒
       → 从"学而思"账户余额扣费 ¥0.05

   │ ⑤ 月底出账单
平台生成账单：本月共调用 1.2 万次，消费 ¥520
```

**v1.2 关键变化**：
- 平台**对内对外统一**，不再"先内部双轨"
- **xiaozhi-server MVP 即接入**（第一个内部超级租户）
- xiaozhi-server 瘦身：剥离 AI 实现，只保留设备协议层
- 平台与 xiaozhi-server **同物理机部署**（localhost 调用，< 1ms 延迟）
- WebSocket **MVP 只做通路 B**（xiaozhi 内部协议），通路 A（外部实时）延后 V1.1

### 3.2 多租户数据隔离示意

```
┌────────────────────────────────────────────────────────────────┐
│ 平台数据库（一张大表 ykt_aisaas_message 存所有租户消息）       │
├──────────┬──────────┬──────────────┬───────────────────────────┤
│ id       │ tenantId │ role         │ content                   │
├──────────┼──────────┼──────────────┼───────────────────────────┤
│ 1001     │ 100      │ user         │ 你好                       │  ← 学而思
│ 1002     │ 100      │ assistant    │ 你好！我是 AI 助手...      │
├──────────┼──────────┼──────────────┼───────────────────────────┤
│ 1003     │ 200      │ user         │ Hello                     │  ← 另一家公司
│ 1004     │ 200      │ assistant    │ Hi there! ...             │
├──────────┼──────────┼──────────────┼───────────────────────────┤
│ 1005     │ 100      │ user         │ 再问一个问题               │  ← 学而思
└──────────┴──────────┴──────────────┴───────────────────────────┘

租户 100 查询时，平台自动加 WHERE tenantId=100 → 只看到自己的 3 条
租户 200 查询时，平台自动加 WHERE tenantId=200 → 只看到自己的 2 条
两个租户互相看不到对方的数据（即使存在同一张表里）
```

### 3.3 关键资源隔离

| 资源 | 隔离方式（用业务话） |
|---|---|
| 数据库表 | 所有客户数据混存，但每行带"客户编号"标签，查询自动过滤 |
| 文件存储 | 每个客户一个独立文件夹 `/tenant/100/...` `/tenant/200/...` |
| 知识库 | 每个客户的知识库单独一张向量表，跨客户检索不到 |
| API Key | 每个客户独立 Key，丢失不影响他人 |
| 配额余额 | 每个客户独立账户，互不挪用 |
| 缓存 | 客户 A 缓存的对话上下文，客户 B 拿不到 |

### 6.3 向量库（PgVector）的特殊之处

普通数据库：搜索 "天气" 只能找到包含"天气"两个字的文档。
向量库：搜索 "天气" 还能找到"今天下雨吗"、"温度怎么样"——**理解意思**。

原理：
```
文档："产品支持 WiFi 6" 
  → AI 转换 → [0.12, -0.34, 0.56, ..., 0.78]（1024 个数字）
  → 存进向量表

搜索："能连 WiFi 吗"
  → AI 转换 → [0.15, -0.31, 0.58, ..., 0.75]
  → 找最接近的几个向量 → 返回原文
```

**每个客户的每个知识库单独一张表**：
- 学而思的"产品手册" → `rag_chunk_tenant_100_kb_5`
- 学而思的"客服话术" → `rag_chunk_tenant_100_kb_6`
- 另一家的"商品 FAQ" → `rag_chunk_tenant_200_kb_8`
- **跨表查询是不可能的**，从结构上保证隔离

### 7.2 "OpenAI 兼容"的价值

**价值**：客户用任何 OpenAI SDK 都能直接接入平台，**改一行配置**就行：

```python
# 原本调 OpenAI：
client = OpenAI(api_key="sk-openai-xxx", base_url="https://api.openai.com/v1")

# 改用本平台（只改 base_url 和 api_key）：
client = OpenAI(api_key="sk-aisaas-xxx", base_url="https://aisaas.ykt.com/v1")

# 其他代码完全不变
client.chat.completions.create(...)
```

**好处**：
- 客户切换成本低（不用重写代码）
- 客户可以同时接入多家平台做容灾
- 后续平台自建模型时，对客户完全透明（base_url 不变）

## 11. 与 xiaozhi 的关系（业务视角，**v1.1 重大修订**）

### 改造前（现状）

```
小智 AI 设备 ──► xiaozhi-server（自研全套 AI 实现）
                   · ChatModelFactory + 7 个 LLM Provider
                   · TtsServiceFactory + 8 个 TTS Provider
                   · SttServiceFactory + 7 个 STT Provider
                   · ChromaVectorStore + RAG
                   · XiaoZhiToolCallingManager + MCP
                   ────────────────────────
                   约 50000 行 Java + ONNX Runtime + 各厂商 SDK（改造前的 xiaozhi）
```

### 改造后（**MVP 阶段即切换**，非双轨）

```
小智 AI 设备 ──► xiaozhi-server（瘦身后）──┐
   WebSocket   · 仅保留设备协议层            │
   Opus 音频   · 仅保留设备/消息管理         ├──► YKT AI SaaS 平台 ──► 外部 AI 服务商
                · AI 调用全部走平台 API       │    （内部超级租户）     OpenAI/阿里/智谱/...
                                              │
其他客户应用 ───────────────────────────────┘
   HTTPS / SSE                                 （同一套平台同时服务内外）
```

### 改造带来的好处

| 维度 | 改造前（自研） | 改造后（接入平台） |
|---|---|---|
| **代码量** | 约 50000 行 Java | 约 25000 行（减少 50%） |
| **依赖** | ONNX Runtime + 各厂商 SDK | 仅一个 OpenAI 兼容客户端（指向平台） |
| **新增 AI 厂商** | 自己写 Provider + 测试 | 平台配置即生效 |
| **新增能力**（如克隆/微调） | 自己开发数月 | 平台上线即用 |
| **统一计量** | sys_message.tokens 粗略 | 平台精准计量 + 月度账单 |
| **运维** | AI 升级要重启 xiaozhi-server | 平台独立升级 |
| **对外议价** | 单家客户量小 | 平台聚合多租户，议价能力强 |

### 改造路径（**两阶段，不再三阶段**）

```
═══ 阶段 1（MVP，0-3 个月，与平台开发并行）═══
   xiaozhi-server：
     ✅ 保留设备协议层（WebSocketHandler/ChatSession/SessionMgr）
     ✅ Persona 改造（注入平台的 OpenAiChatModel/TtsClient）
     ✅ 数据迁移脚本（sys_config/sys_role/sys_template/sys_knowledge_* 迁到平台）
     ✅ feature flag 应急回滚开关（xiaozhi.ai.usePlatform）
     ✅ 灰度环境联调（100 台测试设备）

═══ 阶段 2（稳定期，3-4 个月）═══
   验证 1 个月稳定后：
     🗑️ 删除 xiaozhi-server 的 xiaozhi-ai 整个模块
     🗑️ 删除 xiaozhi 库中已迁移的 AI 配置表
     🗑️ 删除 ONNX Runtime / 各厂商 SDK 依赖
     ✨ xiaozhi-server 彻底瘦身成纯设备协议层
```

### 改造期间的风险与应急

| 风险 | 应急方案 |
|---|---|
| 平台故障导致设备不能用 | **一键回滚**：feature flag 切回 xiaozhi 自研 AI（保留 1 个月观察期） |
| 性能不达标（P95 > 3 秒） | 排查链路：VAD → 网络 → ASR → LLM 首字 → TTS 首音频 |
| 数据迁移丢失 | 灰度环境全量演练 + 生产迁移前备份 + 双写 7 天对账 |
| 设备 Persona 行为不一致 | 迁移脚本 + 100 台设备灰度 + 用户问卷 |

**关键保障**：xiaozhi-server 与平台**必须同机房部署**（局域网 < 5ms），否则设备对话延迟不达标。

### Q1：和直接用 OpenAI / 阿里云 / 百度 有什么区别？

| 维度 | 直接用厂商 | 用本平台 |
|---|---|---|
| 多厂商切换 | 自己改代码 | 配置即可 |
| 多租户隔离 | 自己实现 | 现成 |
| 计费/账单 | 自己做 | 现成 |
| 国产+国外混用 | 自己写适配 | 现成 |
| Web 管理后台 | 没有 | 现成 |
| 知识库/工具调用 | 自己集成 | 现成 |
| 客户支持 | 厂商文档 | 中文本地服务 |
| 合规/数据出境 | 看厂商 | 国产可控 |

### Q2：数据安全怎么保证？

- 所有租户数据**字段级隔离**，DB 查询自动加 `WHERE tenantId=...`，代码层面无法跨租户访问
- API Key 仅哈希存储，泄露后可一键禁用
- 文件存储独立路径，URL 签名访问
- 平台运营人员有完整操作审计
- 后续支持私有化部署（大客户）

### Q3：平台挂了客户怎么办？

- MVP 阶段：单点，挂了客户业务受影响（建议 99.5% SLA）
- V2.0 起：集群部署，单实例挂不影响
- 上游 AI 厂商挂：平台自动 fallback（OpenAI→DeepSeek→智谱）
- 流式调用中途断：客户端可重连

### Q4：能私有化部署吗？

可以。MVP 完成后提供"私有化版"：
- 部署到客户机房
- 一次性 license + 年度服务费
- 适合金融/政府/医疗等合规要求高的客户

### Q5：和 Dify / FastGPT / Coze 等有什么区别？

| 平台 | 定位 |
|---|---|
| Dify / FastGPT | AI 应用开发平台（拖拽编排、聊天界面） |
| Coze | 字节的 AI 助手平台（封装好应用） |
| **本平台** | **AI 能力 API 平台**（给开发者用的"水电煤"） |

本平台**不做应用层**（聊天界面/工作流编排），只做**能力层**。客户可以基于本平台搭建类似 Dify 的应用。
